1 · Overview

MINT Wealth Navigator is a multi-persona web app; the shipped surface is the OEMS trading desk (/oems). It was rebuilt from a Lovable prototype into a production stack and is being wired live against IRESS V4 (SOAP) for the JSE.

LayerTechWhere
Frontend + BFFNext.js 16 (App Router, RSC) · React 19 · Bun · TypeScript strict · Tailwind · shadcn/uiVercel — wealth-navigator-one.vercel.app
IRESS workerBun + node:http; hand-rolled SOAP clientRailway — iress-worker-production.up.railway.app (:8765)
DataSupabase (Postgres + RLS + Realtime)3 projects — see §3
Mental model: IRESS is the source of truth for market + trading data. The Railway worker owns the single IRESS license seat and writes into Supabase. The Next.js BFF reads Supabase (never IRESS directly) and serves the desk. The frontend never talks SOAP.

Naming hazard: both prod DBs get called "production." nnwz… is labelled "MyMint" in AGENTS.md (it was the IRESS-test DB, now promoted). mfxng… is the live consumer app. Always disambiguate retail-prod vs institutional-prod.

Data conventions (important)

  • Prices are in integer cents in securities_c.last_price and stock_intraday_c.current_price. Divide by 100 for Rands.
  • Retail tickers carry a .JO suffix (NPN.JO); IRESS uses bare codes (NPN on exchange JSE). The BFF/worker map between them (strip/append .JO, or join on isin).
  • Retail securities_c has change_price/change_percent (Yahoo) — not prev_close/currency (those exist only in the institutional copy).
  • Client ↔ IRESS account join key: profiles.mint_number ↔ IRESS AccountCode (100% populated; bridge deferred past v1).
  • All migrations are review-only, user-pasted in the Supabase SQL editor. The worker never applies DDL. SQL must be idempotent.

4 · IRESS V4 integration

Session model

Two session types. IRESSSessionStart (1 license, ~2h idle / 24h max) → ServiceSessionStart per service (IOSPlus / IPS / FIXPlus). Credentials are user@company split into UserName + CompanyName. Single CT seat — fault 25008 = no licenses; recovery is auto-kick (SessionNumberToKick=-1) and a logout sequence (ServiceSessionEnd × N → IRESSSessionEnd → 3s).

Price scaling — the keystone

IRESS returns JSE prices inconsistently (some bare Last in Rands, some LastPrice in cents); a naïve heuristic mis-scales sub-R45 stocks by 100×. src/scale.ts:chooseDisplayCents() anchors to the existing securities_c.last_price reference and picks the interpretation whose magnitude matches — bulletproof against the cents/Rand ambiguity, falls back to Rands→cents with no reference.

8 · Price data flow — the Yahoo → IRESS cut-over

Retail securities_c/stock_intraday_c are populated by an existing Yahoo feed today (~15s cadence). The goal: replace Yahoo with IRESS as the source of truth.

  1. Now: BFF reads retail (Yahoo) prices. Worker's retail-ingest loop is dormant (off by default).
  2. Shadow (weekday): set IRESS_RETAIL_INGEST=1 + RETAIL_SUPABASE_* on Railway; worker polls all 246 and logs the IRESS-vs-Yahoo diff, writing nothing (gated by IRESS_RETAIL_DRY_RUN, default shadow).
  3. Validate: re-run /debug/coverage + check scaling on live trades.
  4. Flip: apply supabase/retail/20260614_add_price_source.sql (adds price_source), set RETAIL_PRICE_SOURCE_COL=1 + IRESS_RETAIL_DRY_RUN=0. Worker writes IRESS prices for symbols it covers, tagged iress; Yahoo keeps the rest.
  5. Retire Yahoo per-symbol once IRESS coverage is confirmed complete.
Safety: the retail write path touches only securities_c.last_price + stock_intraday_c — never customer tables — and is double-gated (IRESS_RETAIL_INGEST + IRESS_RETAIL_DRY_RUN). Do not set RETAIL_SUPABASE_* on the Railway worker until the scaling is validated.

11 · Workflows

Deploy

# both Vercel (BFF/UI) and Railway (worker) auto-deploy on push to main
git push origin main

Local dev

cd wealth-navigator
bun install
bun run dev          # http://localhost:3000 (IRESS_MODE=mock by default)
bun run typecheck    # tsc --noEmit
bunx vitest run      # unit tests

Migrations

Review-only. Paste the SQL into the relevant Supabase project's SQL editor by hand (institutional migrations in supabase/migrations/, retail in supabase/retail/). The worker never applies DDL. SQL is idempotent.

Diagnostics

# live IRESS method matrix (re-run after Charles changes anything)
curl https://iress-worker-production.up.railway.app/debug/iress-methods

# read-only retail DB scans (need RETAIL_SUPABASE_* in .env.local)
bun run scripts/scan-retail.ts
bun run scripts/run-coverage.ts

12 · Key decisions

  • 3-DB topology (retail / institutional / staging), compliance-driven. docs/DB_TOPOLOGY_DECISION.md (supersedes the two TWO_DB* memos).
  • IRESS = source of truth; the worker is the sole price publisher; Yahoo is retired per-symbol after validation.
  • Reference-anchored scaling instead of a fragile per-symbol heuristic.
  • Client↔account bridge deferred past OEMS v1 (operator-trading-only first).

13 · Gotchas

  • IRESS ServiceSessionStart HTTP 500 cascades — orders/IPS/FIX+ all fail downstream of it. Fix the session, not the 7 methods.
  • IRESS TimeSeriesGet2 live WSDL ≠ published docs — needs the real WSDL / a working example from IRESS.
  • .JO vs bare codes — every retail read/write must map between them. chooseDisplayCents + the candidate-symbol query handle it.
  • Prices in cents in DB; UI divides by 100. Mixing units = the 100× bug.
  • Two "production" DBs — see the naming hazard in §3.
  • Closed-market (weekend) IRESS values are unreliable — validate on weekday trades.
  • Stale nested wealth-navigator/.git dir exists but git uses the outer repo root.

14 · Getting started (new dev)

  1. git clone github.com/edgeza/Wealth-Navigator → app lives in wealth-navigator/.
  2. Copy .env.example → .env.local; default IRESS_MODE=mock runs fully offline with seeded data.
  3. bun install && bun run dev → /oems. App login is separate from IRESS SOAP creds.
  4. Read, in order: docs/DB_TOPOLOGY_DECISION.md · docs/STATUS_AND_CHARLES_ASK_2026-06-14.md · AGENTS.md (learned conventions) · Documentation & Vision/iress-v4-docs/ (the V4 protocol).
  5. For live data: set RETAIL_* / INSTITUTIONAL_* + USE_SUPABASE_QUOTES=true; never put service keys in client bundles or NEXT_PUBLIC_*.
