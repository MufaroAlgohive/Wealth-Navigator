================================================================================
1. PURPOSE
================================================================================

This is the definitive go-live endpoint list Mint Wealth Navigator will call in
production from day one. It covers 17 V4 methods, organised by IRESS namespace so
each group maps to one provisioning surface. Every method is named exactly as it
appears on the V4 WSDL (verified against the V4 doc set
Documentation & Vision/iress-v4-docs/, master quick reference
10-reference/quick-reference/00-master.md and per-service quick refs, on
2026-06-09). Every method is grounded in a file:line reference in the running
Mint codebase.

Layout for each method:

    Name (verbatim from V4 docs)
    Namespace ............ the V4 service hosting the method
    SOAP service / target  the SOAP service + target namespace
    SOAP action / WSDL op. the WSDL operation / SOAP action
    Direction ............ request/response pattern
    Purpose on Mint ....... 1 sentence: what dashboard/feature uses it
    Code reference ........ file:line where Mint invokes it
    Call rate ............. low / medium / high / streaming
    Idempotency ........... does the method need / support an idempotency key
    Wire-up today ......... "called from UI today" / "internal helper only" /
                            "declared but not yet wired"
    Mock implementation ... real fixture / no-op / throws

2. GROUP A -- Iress Pro (session + entitlement + market-data surface)
================================================================================

The Iress Pro namespace hosts the parent Iress session, the per-service
ServiceSession, and the snapshot + long-poll market-data methods. SOAP endpoint
target namespace: http://webservices.iress.com.au/v4/ .

5. GROUP D -- FIX+ (FIX control/status surface)
================================================================================

The FIX+ namespace in V4 is a thin wrapper around the FIX+ engine -- control
and status only. The actual FIX message stream (drop-copy bytes) travels
over a separate TCP FIX connection that Mint terminates directly; V4 is not
in the FIX bytes path. SOAP endpoint target namespace:
http://webservices.iress.com.au/v4/ . All FIX+ methods require a
ServiceSessionKey (from a prior ServiceSessionStart with Service = "FIXPlus",
Server = e.g. "FIXPLUSAPI"). Header token: ServiceSessionKey.

7. CLOSING REQUESTS
================================================================================

If any method is deprecated, renamed, or pinned to a WSDL version we haven't
seen, please flag in your reply.

For each method, we have provided the code reference where Mint invokes it.
Sandbox access for QA testing is requested.

Mint's ApplicationID discipline follows the V4 doc recommendation:
  Mint-OEMS-<env>-<node>-<guid>
built by lib/iress/index.ts:69 buildApplicationId(envHint, node), with the
GUID generated by crypto.randomUUID() per process.

The IRESSSessionKey / ServiceSessionKey model is the standard two-layer
session (parent Iress + 3 child services: IOSPlus / IPS / FIXPlus), built
in lib/iress/index.ts:76 bringUpMintSession and torn down via
IRESSSessionEnd + ServiceSessionEnd (the latter is declared but not yet
wired in UI; the bring-up helper currently only opens, never closes).

OrderCreate3 uses OrderTag (UUID v4 per attempt) for idempotency; we
respect the documented 5-minute dedupe window. The OrderNoGetByOrderTag
recovery half is on the "likely" list, not the 100% list -- it ships
within one sprint of go-live.

Please confirm receipt and acknowledge that every 100% method is on the V4
WSDL today and not flagged for deprecation in 2026 / 2027.
